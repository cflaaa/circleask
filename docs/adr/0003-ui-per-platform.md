# ADR 0003 · 一套功能，三套界面，文件级隔离

- 日期：2026-11-02
- 状态：已采纳

## 背景

同一个 App 要在手机上竖屏单手用，在平板上横屏配键盘用，在桌面上多窗口用。
三种场景的信息密度差一个数量级，用媒体查询硬适配会互相打架。

## 决定

`src/ui/` 下按端分目录，**互不 import**：

```
ui/shared/    两端都用的最小工具（DOM 助手、格式化），不含布局
ui/phone/     手机：单栏、底部操作条、抽屉式问答
ui/tablet/    平板：左右分栏，书占 2/3，问答停靠右侧 1/3
ui/desktop/   桌面：三栏 + 快捷键 + 可拖拽分隔条
```

样式同样分文件，每条规则都带作用域前缀：

```css
html[data-ui="phone"] .shelf-card { ... }
html[data-ui="tablet"] .shelf-card { ... }
```

**不写 `@media (max-width: ...)`。** 界面风格由设置里的选择决定，
与窗口实际宽度解耦；混用会让「强制平板模式」在窄屏上失效。

## 如何选端

`src/app/container.js` 在启动时决定一次：

1. 读用户设置（`phone` / `tablet` / `desktop` / `auto`）
2. `auto` 时看运行环境：桌面壳 → desktop；触屏且短边 ≥ 600 → tablet；否则 phone
3. 给 `<html>` 打 `data-ui`，动态 import 对应目录的入口

## 代价

- 三套界面有重复的骨架代码（书架列表的渲染逻辑写三遍）。
  **这是故意的**：重复比错误耦合便宜。等真的三端都稳定了，再考虑抽公共组件。
- 改一个交互要改三处。所以规矩是：**用户没说「同步」时，只改一端。**

## 什么情况下该推翻它

当三套界面的差异收敛到只剩 CSS（JS 逻辑完全一致）时，
说明抽象时机到了，可以合并成 `ui/shared` + 三份样式。
现在还不是。
