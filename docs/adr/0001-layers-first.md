# ADR 0001 · 先定边界，再写代码

- 日期：2026-11-02
- 状态：已采纳

## 背景

旧工程的功能与界面是缠在一起长出来的：一个 3500 行的文件里，
算页码的代码和改 `innerHTML` 的代码隔三行。后来虽然按目录拆开了，
但那是**事后按行区间切的**，边界来自「这行原来在哪」，而不是「这行该属于谁」。

结果就是：想换个渲染方式，得先去界面层翻出渲染调用点。

## 决定

新工程从第一行代码起就按四层写，并且**用脚本检查**，不靠自觉。

## 代价

- 前期文件多，一个简单功能要跨 2~3 个文件才写完。
- 端口抽象有学习成本，新人得先看 `core/ports` 才懂数据怎么流动。

## 收益

- 换渲染方案（canvas → img）、换模型供应商、换存储，都只动 `adapters` 一层。
- core 可以脱离浏览器跑测试，不需要 jsdom，也不需要真设备。
- 三种界面共享同一套服务，不会出现「手机端修了、平板端还是老 bug」。

## 什么情况下该推翻它

如果某个功能在四层之间来回改了三遍还是别扭，说明分层划错了，
应该改 `docs/01-architecture.md` 并补一条 ADR，而不是偷偷在 ui 里写业务。
